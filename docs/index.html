Patient Intake Approval Queue

What it demonstrates

The frontend could have shipped in an afternoon from an AI app builder. This project is everything IT needs before that frontend can touch a real patient. Speed is not the argument. Control is: the business logic lives in one typed API layer a technical evaluator can read and trust.

Versioned triage rules

The active rule set decides each priority and records the version and reason on the intake. Older intakes keep the version that routed them.

API-layer RBAC

An auth table plus a per-endpoint role guard. Wrong-role writes are rejected on the server with a 403, never with row-level security.

Append-only audit

Submitted, evaluated, claimed, approved, denied. Every change writes one row with the actor and time, and is never updated after.

API surface

Every endpoint lives under one API group, intake.

VerbPathWhat it enforces
POST/api:intake/auth/loginPublic. Verifies the credential, mints a token, returns the role.
POST/api:intake/submitIntake clerk. Matches or creates a patient by MRN, opens the intake.
POST/api:intake/evaluateIntake clerk. Runs the active rules, stamps priority, version, and reason.
POST/api:intake/queue/claimClinician. Claims an open queue item.
POST/api:intake/queue/approveClinician. Approves a claimed intake.
POST/api:intake/queue/denyClinician. Denies a claimed intake with a reason.
GET/api:intake/queueClinician or viewer. The queue, emergent first.
GET/api:intake/detail/{intake_id}Any signed-in user. The intake, its routing rule, and its audit trail.
POST/api:intake/rules/activateClinician. Publishes a new triage rule version.
GET/api:intake/rulesAny signed-in user. Every rule version, active flagged.
GET/api:intake/seedPublic. Seeds the demo data (idempotent).

The screens

  • Sign in / role switcher. Pick a seeded user. The role decides what the API allows.
  • Intake. Submit an intake, then run the rules and watch a emergent, urgent, or routine priority get assigned.
  • Review queue. Emergent first. A clinician claims, approves, or denies; a viewer or clerk is blocked at the API.
  • Intake detail. The patient, the exact rule version and criteria that fired, and the append-only audit trail.
  • Rule versions. Every version with the active one flagged, and a clinician-only publish form.
